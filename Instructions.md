## Технологии и стилизация

Используй следующий стек:

- React
- TypeScript со строгой типизацией
- Vite
- SCSS / Sass Modules для стилизации компонентов
- React Router для маршрутизации
- TanStack Query для работы с серверными данными
- Zustand для глобального состояния интерфейса
- React Hook Form и Zod для форм и валидации

Не используй Tailwind CSS.

Не устанавливай готовые UI-библиотеки, библиотеки компонентов, наборы иконок или готовые дизайн-системы без моего прямого разрешения.

## Моя роль в разработке дизайна

Дизайн приложения я разрабатываю самостоятельно.

Я буду самостоятельно создавать и добавлять:

- SCSS-стили;
- иконки;
- изображения и аватары;
- цветовую палитру;
- шрифты;
- дизайн компонентов;
- анимации;
- визуальные состояния интерфейса.

Не придумывай и не меняй дизайн самостоятельно. Не пытайся улучшать визуальную часть по своему усмотрению.

Твоя основная задача — архитектура приложения, бизнес-логика, React-компоненты, работа с данными и функциональность.

Если для реализации функции нужен новый визуальный компонент, создай минимальную React-структуру с корректными классами и семантической разметкой. Не добавляй декоративные стили, цвета, тени, градиенты или анимации без моего запроса.

Если я предоставил готовую разметку, SCSS, иконки или другие ресурсы, используй их и не заменяй собственными аналогами.

Если визуальная часть ещё не реализована, создай функциональную структуру с понятными CSS-классами и подключением SCSS Modules. Не генерируй собственный дизайн вместо моего.

## Правила работы с SCSS

Используй SCSS Modules для изоляции стилей компонентов.

Пример структуры:

src/
  components/
    ChatList/
      ChatList.tsx
      ChatList.module.scss
    ChatWindow/
      ChatWindow.tsx
      ChatWindow.module.scss
    MessageInput/
      MessageInput.tsx
      MessageInput.module.scss

Для общих стилей используй отдельную директорию:

src/
  styles/
    _variables.scss
    _mixins.scss
    _functions.scss
    global.scss

Создавай только действительно необходимые файлы.

Не дублируй глобальные стили в каждом компоненте. Не создавай отдельные SCSS-файлы без необходимости.

Не меняй существующие имена классов, структуру SCSS или дизайн-токены без согласования.

Если я предоставляю готовые стили, интегрируй компоненты с ними, а не переписывай стили под свою реализацию.

Не добавляй inline-стили, если задачу можно решить через существующие SCSS-классы.

Не используй !important без обоснованной необходимости.

## Правила создания React-компонентов

Разделяй визуальную разметку и бизнес-логику.

Используй понятные и стабильные имена компонентов и классов.

Не помещай всё приложение в один компонент.

Не смешивай запросы к API, состояние чатов и разметку в одном файле.

Предусматривай состояния загрузки, ошибки и отсутствия данных, но не придумывай их визуальное оформление самостоятельно. Подготовь необходимые классы и структуру, чтобы я мог стилизовать их.

Если для новой функции требуется изменить существующий интерфейс, сначала определи минимально необходимое изменение и не затрагивай остальные части дизайна.

## Первоначальный этап разработки

На первом этапе:

1. Настрой React, TypeScript и Vite.
2. Настрой SCSS и CSS Modules.
3. Настрой маршрутизацию.
4. Настрой TanStack Query и Zustand.
5. Создай архитектуру модулей.
6. Подготовь типы пользователей, чатов и сообщений.
7. Создай mock-данные.
8. Реализуй функциональную основу списка чатов и окна переписки.
9. Добавь необходимые классы и структуру для моей дальнейшей стилизации.

Не создавай самостоятельно законченный дизайн мессенджера. Сосредоточься на функциональной основе и интеграции с моими стилями.

Перед изменением существующих стилей сначала изучай их. Если не хватает иконки, изображения, цвета или другого ресурса, сообщи об этом и дождись моего решения, если ресурс действительно необходим.
